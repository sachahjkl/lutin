# Lutin v0.7.0

## Hardware rendering

- Render meshes through the DS geometry engine, with hardware transforms, projection, rasterization, and depth testing.
- Render rectangles, lines, sprites, tilemaps, and text through the same engine.
- Store sprite textures in program-owned VRAM arenas and use one shared font atlas.
- Capture the hardware output for PNG images and seeded tests.
- Reject frames that exceed geometry, command, or texture budgets.

The host retains a software reference renderer for logic tests.
Audio continues to use the console's hardware square-wave and noise channels.

## Other optimizations

- Remove the per-frame RAM framebuffer transfer.
- Copy console maps only when their contents change.
- Cache conversation pages by revision, scroll position, and tool-detail mode.
- Track stream buffer lengths instead of rescanning accumulated responses.
- Report complete main-loop work, UI work, agent work, transfer bytes, and skipped VBlanks.

## Verification

Hardware pixel tests cover sprite transparency, scaling, accented text, background/HUD ordering, mesh depth, and clipping.
Regression tests cover startup rollback, clipping expansion budgets, and texture cleanup after allocation failure.
An independent subagent reviewed the implementation and its fixes.

The 2D and 3D recordings replay recorded model responses while executing the real agent, tools, and runtime.
The emulator displays `REPLAY GPU`. These recordings are not live console inference.
Recorded conversation text still describes the earlier software renderer; the current replay executes the GPU backend.
DS-mode emulator measurements do not establish physical-DSi frame rates or network reliability.

## Upgrade

Replace `/roms/nds/lutin.nds` with the new ROM.
Draw complete frames in creations: background, meshes, then HUD.
See [Hardware rendering](https://github.com/sachahjkl/lutin/blob/main/docs/hardware-rendering.md) for rendering limits and VRAM ownership.
